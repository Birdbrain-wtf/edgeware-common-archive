There were a lot of exciting Web3 Foundation grant winning projects in Wave Three of the grants program - too many to cover in one post! Here, I'll share some details about two more projects: the pLibra bridge from LibraChina and a Blockchain Package Manager from Blockdaemon.

**pLIBRA Polkadot Bridge from LibraChina**

The pLibra project includes a bridge between Libra and Polkadot, a privacy-preserving Libra token, and a dApp ecosystem in Polkadot for Libra users. A cross-chain bridge is a way for networks to communicate, sending assets between chains. pLibra is made by LibraChina, a group dedicated to building applications on Libra. Co-founder Hang Yin took some time to answer my questions about project.

*What does LibraChina want users to know about the pLibra Polkadot bridge?*

pLibra is primarily a cross-chain bridge meant to allow for private transactions for Libra users, as well as opportunities for developers to build private dApps.

As Yin emphasized, pLibra, as an app with a token, is not a blockchain or even just a privacy token. Instead, it is the first application built on Phala Network, the smart contract blockchain at the core of LibraChina technology. According to Yin, Phala Network allows for a different kind of confidentiality than other privacy-focused blockchains.

While other confidential transaction chains use privacy coins, the goal of Phala Network is to secure privacy for all arbitrary information within smart contracts. The Phala white paper states that this is accomplished by introducing “an Event Sourcing / CQRS architecture into a [Trusted Execution Environment] TEE-blockchain hybrid system to archive cross-chain interoperability for the confidential smart contracts.”

Yin believes this allows for many more use cases, as Phala is meant to be a multi-purpose confidential platform.

*What does their roadmap look like?*

Yin outlined both short-term and long-term goals for the pLibra project, starting with building a minimal viable product of the bridge. By the end of 2019, the team expects to build a Proof of Concept (PoC) showing that confidential transactions can be run between Libra and a pLibra testnet using test Libra coins and existing Substrate infrastructure (Substrate SGX). While the eventual goal is for pLibra to run on top of Phala network, the pLibra testnet will have a single node and be used to show PoC.

In the longer term, the team hopes to launch the Phala Network in the spring of 2020 as a parachain on Polkadot, followed by a mainnet launch that summer. After the mainnet launch, the team plans to recruit miners and elect gatekeepers, a role that Yin compared to that of block producers in that it serves to secure the network. This timeline generally matches the launch plan for the Libra mainnet.

When Libra mainnet is released, pLibra will be officially launched. In the interim, Yin suggested that they may begin developing private bridges for other blockchains, including BTC and USDT.

*Why are they interested in building on Polkadot?*

Yin stated that the motivation for expanding pLibra to Polkadot lies in a desire for their technology to benefit the entire Web3 ecosystem. In Yin’s words, “Libra users have the privacy protection requirement which matches the vision of Web3.” Yin cited Libra as having 2.7 billion potential users and shared hopes that this user base can give vast momentum to the adoption of blockchain technology.

Yin further explained that among interoperability projects, Polkadot is the best fit for Libra’s vision. He emphasized Polkadot’s focus on facilitating blockchain communication, rather than simple token transfers, and reiterated the desire to expand Phala Network’s infrastructure for general-purpose confidential smart contracts beyond privacy-preserving tokens.

**Blockchain Package Manager for Polkadot from Blockdaemon**

Blockdaemon is working to simplify the process of creating scalable blockchain networks. This is according to Blockdaemon Director of Marketing Katie DiMento, who offered me some insight into the Blockchain Package Manager that Blockdaemon is working on with their Web3 grant.

*What does Blockdaemon want users to know about the Blockchain Package Manager (BPM)?*

With Blockdaemon’s BPM, it will be possible for anyone to deploy a node across a diverse set of blockchain protocols with just a download. The tool is meant to provide early-stage projects with support for documentation and technical needs. Moreover, there is a back-end interface to allow for professional users to monitor their nodes.

The project also emphasizes security. While Blockdaemon receives telemetry information and gives recommendations and alerts to nodes, they do not have direct access to BPM nodes. However, the collection of metrics and monitoring services still give users basic insights. This is meant to let developers focus on the projects they’re passionate about, instead of foundational infrastructure challenges.

The BPM gives new protocols and easy way to onboard node operators, too, helping facilitate more effective development in this way.

*What does their roadmap look like?*

The Blockdaemon team plans to have their Web 3.0 Foundation grant completed by the end of this month. DiMento outlined their follow-up plans for the BPM in these steps:

- Integrate Polkadot parachains, as well as other blockchain protocols.
- Build a full open source software suite including an option for users to create their own packages by the end of November.
- Launch a Blockchain Package Registry, where users can upload their own packages.
- Integrate features into the Blockdaemon dashboard.

DiMento also laid out some long-term features they’re thinking about:

- “Snapshotting the blockchain/ledger and starting new nodes from pre-synced snapshots will allow for significantly shortened sync time.
- An encrypted backup of node keys and configuration makes it easy to spin up a “twin” of a node. This can be used for disaster recovery as well a high availability cluster scenarios.
- Cluster support for load-balancing, blue/green deployment upgrades as well as disaster recovery.
- A transaction manager to provide a unified API across all supported blockchain protocols that allows sending transactions from a number of clients to a blockchain node cluster. It will take care of concurrency issues (e.g. nonce management) as well as transaction monitoring.”

*Why is Blockdaemon building for Polkadot?*

DiMento believes that Polkadot offers unique functionality, and described the project as “a promising new ecosystem that we want to be part of.” She went on to state that the BPM can allow parachains to be deployed with a standard process with just a few steps, as the package manager works very well for the parachain model thanks to Parity Substrate.

**A Quick Recap**

All of these conversations with Web3 grant winners have made clear the amazing intention and vision behind all of the winning projects. They are designed to be truly useful, and to take advantage of the novel ecosystem structure that Polkadot is creating. There is an evident awareness of industry standards and the current needs of users in each of these road maps, but the motivations of the teams are still forward-thinking.

I want to extend my gratitude to the founders and team members I've spoken to for taking the time to share with our community. It will be exciting to see where these projects and teams go in driving Web3 growth!
