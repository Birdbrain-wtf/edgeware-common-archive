The Edgeware ecosystem would benefit significantly from a high quality, open-source mobile wallet. There are a few ways we could implement one:

1. We could partner with an existing open-source wallet.
2. We could work with an independent developer to build a new wallet from scratch.
3. We could use exchange and blockchain partnerships to integrate with another ecosystem's wallet (e.g. partner with Sora → integrate with Fearless Wallet).


But each of these approaches involves a lot of uncertainty, management bandwidth, and time. Building a crypto wallet isn't technically an extremely hard problem, but making it fast, performant, and easy to use is difficult, and commissioning a wallet would usually require involving a long-term committed team with a high design bar, which is incredible challenging to do in crypto where the demand for that kind of team is overwhelming.

Finally, Edgeware has somewhat different needs that other networks:

- We aren't an interoperability network like Polkadot or Kusama, but an end-user facing network. While Kusama and Polkadot wallets are implementing WalletConnect, their timeline is stretched out far longer than ours.
- We aren't an EVM-on-Substrate platform like Moonbeam that can just fork existing Ethereum wallets.
- There are only a few good Polkadot ecosystem mobile wallets right now, and it's unclear what kind of support we will receive from them as we aren't a relay chain.


We are more focused on being a sovereign community-run network, so ideologically it makes sense to have an independent wallet that focuses on supporting Edgeware.

**Layer Wallet**

This thread proposes to fund and build Layer Wallet, a mobile wallet for the Edgeware ecosystem that prioritizes UX, simplicity, and extensibility.

The project is based on an idea that I've been exploring since the beginning of the year -- instead of building a wallet from scratch, the project is to fork Signer, remove the assumption that the app will only be used offline, add in wallet features like the ability to view and send balances, and modernize the user interface.

Since Signer is already a working Android and iOS app with Edgeware support, the dev process can be entirely focused on user experience.

The project would include:

- Forking, customizing, and improvements
- Support showing your balance (and calculating free and illiquid balance)
- Support maintaining an address book (by QR code or pasted string)
- Support sending EDG to an address in your address book
- Support switching between multiple addresses
- Support switching between different nodes
- Support selecting your own custom node
- Usability
- Clean up Parity Signer, make it smooth and fast
- Zero lag (Flutter is laggy)
- Haptic feedback, animations, and transitions where appropriate
- Adding a dapp browser with support for Polkadot transaction signing
- Nobody has done this before. We would need to reimplement a large part of the polkadot-js extension on mobile. It's also possible we could draw from new standards being developed on the Kusama/Polkadot side, but currently that's an unknown.
- Platform support: iOS and Android (via TestFlights, apk, and App Store if possible)
- All open source, GPLv3


[Initial designs are here](https://www.figma.com/file/gYa6b6nDvG4OHqBRyfabji/Lattice-Wallet?node-id=0:1).

All designs were made with a mind to retrofitting Signer to become an easy to use Edgeware wallet. Anyone who has used Signer today is probably familiar with the UX traps there. However, Parity has good engineers and the underlying codebase is quite sound.

I started exploring whether this would be a good idea at the beginning of March by resetting the Parity Signer codebase. Jake Naviasky (who wrote much of the Commonwealth governance middleware) has been helping with the process. At this point we've made substantial modifications to the Parity Signer code and tested the app on both iOS and Android. We believe this is the most expedient path forward and will produce a good user experience, and extensible platform for other apps to build on top.

**Philosophy**

Be user end user focused. Less Metamask, more Rainbow Wallet. Less Cosmostation, more Terra Station.

**Proposed Deliverables**

- **Wallet functionality: **Ability to store and send EDG, manage an address book, create or import mnemonics, switch nodes. Ability to see whether your current balance has any locks or illiquidity restrictions imposed on it. Ability to switch nodes.
- **Dapp browser: **Ability to visit web pages in a dapp browser, and use the polkadot-js interface.
- Deployment to the iOS app store OR a TestFlight store such as [airport.community](https://airport.community/) which will make the app downloadable.
- Making an APK available on Github for Android users.
- All code available on Github under a GPT-3 license.


We estimate this is a 3 month project for a team of 2.

We plan to propose for 3,800,000 EDG for this first phase. We used a spot price of $0.038 to set this amount... it seems in line with other proposals for e.g. Fearless Wallet Phase 1 / Phase 2, considering that the scope outlined includes a fairly complex dapp browser and transaction signing project.

We would make a similar sized proposal for any phase two, which would potentially include:

- EVM support (wallet and dapp browser)
- Screen for swapping EDG, using any AMMs/stablecoins that deploy on Edgeware
- Screen for bridging EDG, ETH, and other tokens over chainbridge


Another question might be, how does this tie in with the current Commonwealth Interface proposal that's still being worked on? As is, we're wrapping up work on that proposal over the next couple of weeks. Offchain polls is the last feature that remains to be added, and there are some smaller bounty and search improvements remaining. But all of that work would be wrapped up before this proposal finishes voting.

**Maintenance**

Maintenance of wallets and infrastructure is an unsolved problem in crypto. We may make maintenance proposals to the Edgeware treasury starting one year from the delivery of the app.

However, for the short term, we expect to fund maintenance through proceeds from this proposal and any phase two proposal/tech improvement/extension proposals.

**How this fits into the ecosystem**

As currently stands, there are a few main mobile wallets in the Polkadot ecosystem.

- Fearless Wallet is built in Swift and Kotlin. It's fast, well designed, and has an ambitious roadmap. The latest version of the wallet only supports a few limited features however.
- Polkawallet is built in Flutter. It's the most feature complete wallet today, with support for sending balances, staking, and democracy/council governance (all of those are "apps" built in a separate tab) but there is some amount of glitchiness in the interface that makes it difficult to use for handling large balances where a lot of confidence is needed.
- Parity Signer is built in React Native. It's a "signer, not a wallet", which means that it expects polkadot-js to construct transactions for it, which it can then sign. It has advanced support for multiple networks - including Edgeware, Ethereum, Polkadot, and Kusama, as well as custom derivation paths. However given all this complexity the interface very unintuitive. The product owner of Signer also left Parity a while ago, so maintenance has been handled by a mix of different engineers, none of whom appear to be full time.
- Math Wallet supports several dozens (?) chains including Edgeware and many other Substrate chains. It supports staking as well; however, some people have reported bugs and stuck funds while using the wallet, and the UX is while feature-complete not entirely optimal.
- Edge Wallet (by Shady, from Webb) is a nice Flutter wallet that supports retrieving your balance and sending balances, based on the Rainbow Network mobile app. There are still many features that would need to be added, ones which are already present in Parity Signer.


Fearless is the most confidently usable mobile wallet in the ecosystem by far. We should figure out how to work with the Sora ecosystem to get Edgeware and EDG tokens supported in Polkaswap - but that looks like it will happen late in the year at best.

We could also fork Polkawallet, but maintainability of forks is always a concern. Polkawallet is complex - with many apps for Acala, Laminar, etc. - and we'd have to strip those out.

Forking signer is a "third way" approach and that's the one we've chosen instead.

The strongest reason to develop this project is to have an extensible React Native platform that other protocols, like Webb, Decent, and any AMMs or stablecoins can build upon . RN has been a familiar platform for most developers we meet, even those who have not spent a lot of time on mobile apps.

**What this proposal does not include**

Native support for staking, democracy, and council. Substrate staking is complex so we will steer users to the polkadot-js interface for those actions instead.

Support for a full history of your transactions. That would require an external indexer, which may or may not be available - we will try to include it, but no promises here.

Support for chains other than Edgeware. However, we may seek to support Kusama, Polkadot, and/or Ethereum; this is to be determined.
