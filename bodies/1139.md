**Cross system doc support**

It will be important that we have proper EVM documentation for setting up pre-requisites and developer environments for every machine (Mac OS, Windows) → Someone with Linux can look into support on the Linux side. This will ensure that there is no discrepancies in information throughout the documentation for people who may be using a different machine than what the author of the documentation suggests. 

**Continue preparing resources for EVM docs: development environment (hardhat), pre-requisites, walkthrough, deployment, external resources**

Furthermore, documentation will begin to be written for overhauling our EVM and to create an easy, understandable reference for anyone to go to who might be struggling with using EVM on Edgeware or where to get started. Currently, hardhat seems to be the best option for the first guide and I’m going through the different guides and tutorials that are available on hardhat as well as moonbeam to then port them over into main.edgeware.wiki written in context of Edgeware’s parameters. I’ll be gathering as much resources over the next week as possible and create drafts for this information which will then be peer reviewed to ensure that only relevant information is being drawn out and presented within the documentation.

**Faucet integration on Discord**

So far, it was worth noting the faucet integration on Discord as a bot that Moonbeam uses to fund testnet accounts via metamask found [here](https://docs.moonbeam.network/getting-started/testnet/faucet/). Our current faucet is hardly mentioned within the documentation and without context may be confusing to some. This discord integration would add a couple of key benefits.
- A revised page could be added within documentation to guide users through the process of using the bot on Discord to found their testnet accounts for deploying smart contracts.
- It would encourage developers within our telegram channels (especially builders guild) to migrate over to the Edgeware discord. With embedded features, it would be necessary to use Discord, and hopefully mitigate the need for multiple communication platforms.
- This feature is very user friendly, and will offer a more instrumental experience for anyone looking to build on top of Edgeware.


**Developer section revamp to better target different developers and their individual needs**

It may be worth noting that we should also strive for a more pronounced section within the documentation that is a proper jumpstart for developers. Primarily, this would alleviate the amount of questions being asked on how or where to get started within the builders guild channel and create a more streamlined pipeline which anyone can refer to for someone who raises the question. There should be clear paths that are laid out in an easy to understand manner similar to Substrate’s tutorial section found [here](https://substrate.dev/en/tutorials). Our current layout does well in presenting the basic necessities required to begin developing on Edgeware, but funnels everyone into the same category. For different skill gaps, and for individuals working with different languages, categories of projects, or different development environments, it’s beneficial to tailor those developers with subsections that fit their individual needs. I’d love to hear feedback on what everyone would like to see within the documentation to create a more enjoyable experience for all of us.

**Builders Workshop shelved until relevant EVM docs are available**

Lastly, the first batch of material to be covered on the Builders Workshop live sessions is going to be covering everything EVM and walking participants through step by step on how to create smart contracts on Edgeware using the Ethereum Virtual Machine. With that being said, the start date for the first session is currently blocked and will be shelved until documentation for EVM has been fully produced and revised so that everyone is able to follow along together and also act as a resource for participants to refer back to the documentation as we proceed through the material.
