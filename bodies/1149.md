Hi everyone,

A critical bug was recently uncovered in the Rust EVM crate used by Edgeware and other Substrate chains, which allows certain transactions to be crafted that could cause nodes to run out-of-memory.

The issue has been patched in the latest version of the EVM crate. We've upgraded the Edgeware runtime to use the updated crate at commit hash **dccb703**: 
[https://github.com/hicommonwealth/edgeware-node/tree/drew-fix](https://github.com/hicommonwealth/edgeware-node/tree/drew-fix)

We've issued a runtime upgrade to update the chain to this latest version. It is currently **Democracy Proposal 33** and, at the time you're reading this, will be in voting as **Referendum 37.**

**EDIT:** We are also working on issuing a fast-track proposal that will have a shorter resolution time. Will update here with more details as that happens. **This upgrade is being voted on as fast-track referendum 38, with voting open through Saturday, May 15 10pm PT.**

## Verifying the build

To verify the build, we’re using nightly-2021-03-15 with the chevdor/srtool Docker package. There is a minor issue with the Docker package that requires you to create a replacement lib.sh file with this content:
#!/usr/bin/env bash
vercomp () {
        return 0
}
You should create the above file and save it somewhere, such as your /tmp directory:
vim /tmp/lib.sh
chmod a+x /tmp/lib.sh
Once you've created the file, substitute it into your docker environment when you run srtool, like so:
alias srtool='docker run --name srtool --rm -it -e PACKAGE=$PACKAGE -v /tmp/out:/out -v /tmp/lib.sh:/srtool/lib.sh -e RUNTIME_DIR=node/runtime -v $PWD:/build -v /tmp/cargo:/cargo-home chevdor/srtool:$RUSTC_VERSION'
srtool build edgeware-runtime
This should produce output that matches the proposal hash on the chain, as well as the IPFS and SHA256 hash above.
