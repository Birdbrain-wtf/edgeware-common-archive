## Takeaways

- Iterative Comparison Algorithms face the problem of ranking abstract value by judging value based on a comparison, rather than trying to quantify an abstract worth. 
- There is an obvious challenge to this model: the set of people using the ICA to make the ranked list could be implicitly biased, or explicitly collude to manipulate the outcome.

### How can we rank something with abstract values? 

I want to share an alternative to [quantifying reputation as a way to judge value](https://commonwealth.im/edgeware/proposal/discussion/129-leveraging-reputation-with-blockchain). Instead, I want to examine an Iterative Comparison Algorithm - an algorithm that decides the value of something based on its comparative value, as introduced by Cent.

The clearest blocker to implementing reputation in formal systems is that reputation is inherently abstract. This is the same issue that Kevin Owocki brings up as a [challenge for funding open-source development](https://commonwealth.im/edgeware/proposal/discussion/116) - that it’s not possible to accurately judge how much a developer should be awarded for their work because the value of the work is inherently abstract. This problem of judging abstract value comes up in a lot of places, and Iterative Comparison Algorithms face it by not quantifying value, but instead building a ranking based on a comparison. 

The ICA would give you a choice between two things, and have you choose which is better. This is much easier than trying to assign an arbitrary number or to choose a limited set of parameters to judge value on. And if you were able to get enough people to answer the survey, you would get a reasonably “objective” answer.

Of course, there are obvious challenges to this model. The set of people taking the survey could be implicitly biased, or explicitly collude to manipulate the outcome. This wouldn’t be such a big problem if you were able to give users a huge set of choices that were randomly presented, but if you were trying to sort a smaller list, it’s hard to see any way around the collusion risk. 

You could potentially use a model like holographic consensus to fight collusion. The original proposal for holographic consensus describes a prediction market that helps define which proposals in a community are likely to pass and should be given more attention (fmatan). In this context, that sort of prediction market could be used to predict the outcome of the ICA ranking, and then used as an auditing layer.
