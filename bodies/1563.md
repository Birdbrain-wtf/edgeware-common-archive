This is a short post about basic Edgeware governance standards and was prompted by a lively debate ahead of the New-Futures proposal regarding the use of SimpleMajority voting.  

## **What are governance standards?**

We have a blockchain that enshrines the basic rules of Edgeware into on-chain code - how balances, transactions, voting, upgrades and funding amongst others relate to each other and the processes needed to execute certain actions. 

These automated processes work well at the most basic level, however decisions are nuanced, people interpret things in different ways and so we also need some simple off-chain governance standards that allow us define the way the community interprets and uses the basic functionality. 

## **Why do we need governance standards?**

Often standards are already informally agreed, however this leaves room for later disagreement, so we should have a small number of simple but formalised standards that we can return to. 

Having a few basic standards is vital as we move forward as a project - we don't need loads, but these standards should gradually emerge over time as we debate / discuss and iterate.

In essence we take an informal **belief** aka "We believe that proposals should all be decided via a simplemajority vote..."  and formalise this belief into a governance standard. 

## **Proposed Governance standard: SimpleMajority Treasury Proposals**

Currently when anyone puts forward a treasury proposal to a public referendum, the process uses the [SuperMajority standard.](https://wiki.polkadot.network/docs/learn-governance) 

This means that proposals that are put forward can be easily blocked by a small number of people, or even a single individual or group, even if the proposal has broad backing by a large number of smaller community members. 

For the last few proposals, there has been an informal agreement that we put proposals to a SimpleMajority rather than a SuperMajority, meaning they are biased for broad community backing.  

The way this currently works is that we (council members) construct a fairly complex extrinsic function via Polkadotjs that links a Treasury Proposal to a SimpleMajority referendum. 

Assuming a proposal is not mallicious and contains all necessary information* for a vote then 8/13 council members need to approve the decision to run a SimpleMajority which moves the proposal into the queue and on to voting.

## **Where do we host these standards?**

For this specific governance standard we can simply add it to the proposal template or maybe create a separate Proposal Process document. 

In general these standards would become part of the projects documentation.
