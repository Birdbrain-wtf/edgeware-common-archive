## Takeaways

- When currencies are created or old currencies change their names, there are challenges to helping user communities navigate the nomenclature shifts. In the crypto community, there is even more chance for confusion given both how abundant and how similar currency names and abbreviations are.
- A solution to these challenges, as well as the issue of the limited namespace for currencies, could be to set up a Currency Name Service: a DNS-like system for currency name registration (but decentralized).
- Are there challenges to creating this Currency Name Service? How can we best set up a network for decentrally securing the registry? What sort of registration bid process would best fit a Currency Name Service?


------------------------------------------------------------------------------------------

In 1993, Mexico changed the name of the peso to the “nuevo peso.” They minted new notes, and the value of 1000 pesos became one nuevo peso. They started out by denoting the new currency with an “N” before the word peso, but in 1996 they dropped the N and simply used the original “peso” - even though the meaning behind the name had a very different value. Today, the peso is still technically the nuevo peso. The currency abbreviation, which before 1993 was MXP, is today MXN: the Mexican Nuevo Peso. 

So what did everybody do with their old peso notes after 1993? At what point did people stop using their old peso notes, and transition to the nuevo peso? When did people start using peso to refer to nuevo peso, instead of the original currency? When did the original currency lose its value?

These are questions that are relevant today in the case of MakerDAO’s recent [transition to Multi-Collateral Dai](https://commonwealth.im/edgeware/proposal/discussion/126-potential-lessons-from-multicollateral-dai). With the transition came a blog post that Multi-Colateral Dai would now take the official name Dai, while original Single-Collateral Dai would start to be called Sai. But a simple memo doesn’t make the process of transitioning currency names and meanings any more straightforward for a community. Maybe most of the community saw the blog post, or heard about it from fellow community members, and they make the terminology switch and understand clearly what it means. But what if there is a subset that doesn’t change over to MCD, and instead continues using Sai - only they keep calling it Dai? Or if there is a group that somehow misses the fact that there was a change in currency nomenclature, or doesn’t understand it? 

At very least, it would be useful to have a recognized resource for verifying and explaining changes to currency nomenclature. Even outside of the issue of planned changes to currency names, given that many existing cryptocurrencies share similar names and abbreviations, this sort of resource could be key. So, what if we used a DNS-like distributed registry for the names of tokens?

The concept, designed by Thom Ivy, is founded on the idea that because there is limited namespace for currency names and abbreviations, there is an opportunity to create a market. Registering a name could be similar to registering a website with DNS - only with improved standards for securing the registry. One of the key criticisms of DNS is that it relies on centralized authorities for verification. A currency nomenclature registry would need to be verified securely and trustlessly. This could be implemented with an ENS-like smart contract registry, or with a system like that supported by Handshake and Namebase. 

Implementation of a decentrally-secured Currency Name Service would help avoid the challenges faced when currency nomenclature and underlying value are changed. It would serve as a trusted resource on the state of currency nomenclature, helping people navigate any shifts. Moreover, it would make it easier (and reduce the potential for scammers) to register a new cryptocurrency name. We could start similarly to Handshake by reserving the top 1,000 cryptocurrency names in the registry (this number subject to revision). Then, remaining currency names could be acquired either on a first-come, first-serve basis, with a Vickrey auction style (like the Handshake model), or some other mechanism. 

## Application

When currencies are created or old currencies change their names, there are challenges to helping user communities navigate the nomenclature shifts. In the crypto community, there is even more confusion, given both how abundant and how similar names and abbreviations are. Creating a Currency Name Service is a clear solution to these problems, as well as the issue of the limited namespace for currencies. 

Remaining questions:
- Could there be unforeseen challenges to implementing a Currency Name Service? 
- What sort of registration bid process would best fit this sort of service? 
- How can we best set up a network for decentrally securing the registry?
