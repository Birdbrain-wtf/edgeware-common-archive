With great excitement, we're announcing what will be the final testnet before our updated mainnet launch. This testnet features all the balances from the lockdrop (except Commonwealth's allocation) as well as updates from the past months, stabler substrate features, and updates to validator controls.
In this testnet, all normal slashing behavior is enabled and we'll be using it once again to check whether there are issues with the slashing functionality. We cannot stress this enough but you should take extra care to setup your validators and session keys correctly. In this document we'll outline how to connect to the testnet.

## Connecting with the Edgeware node
The v099 testnet chainspec is located in the chains/testnet-0.9.9.chainspec.json. To run it you can use the edg-0.9.9 flag by running the following command after building your Edgeware node.

./target/release/edgeware --chain=edg-0.9.9
You should fully sync the node before you start validating. In order to validate on the Edgeware network follow the instructions in the next section. The are largely the same as they have been.

## Validating on the Edgeware network
The v099 testnet requires validators to manage 4 validating keys for the Aura, Grandpa, ImOnline, and AuthorityDiscovery modules.

1. Aura keys (ed25519)
2. Grandpa keys (ed25519)
3. ImOnline keys (ed25519)
4. AuthorityDiscovery keys (sr25519)


Now while running your full node to sync or afterward, you can start to set up your session keys for the node. The command for inserting keys and rotating keys is the same as it has been. To rotate new session keys, run the following while your node is running:

curl -H 'Content-Type: application/json' --data '{ "jsonrpc":"2.0", "method":"author_rotateKeys", "id":1 }' 127.0.0.1:9933
To insert existing session keys, you can run for each key the following command while your node is running:

curl -H 'Content-Type: application/json' --data '{ "jsonrpc":"2.0", "method":"author_insertKey", "params":["KEY_TYPE", "SEED", "PUBKEY_HEX"],"id":1 }' localhost:9933
The four key types you will enter individuals are:

- aura for Aura keys
- gran for Grandpa keys
- imon for ImOnline keys
- audi for AuthorityDiscovery keys

Finally, to connect as a validator, you should run

./target/release/edgeware --chain=edg-0.9.9 --validator
Your node now can sign the data it needs to in order to participate in the consensus, but the rest of the network does not know about these keys nor are they configured to be selected in the consensus and block authoring mechanisms.
To do so you can use the Polkadot UI or the Edgeware CLI. To do so using the Polkadot UI, you can follow the normal tutorial on the Polkadot website: [https://guide.kusama.network/en/latest/try/validate/](https://guide.kusama.network/en/latest/try/validate/)

## Using the Edgeware CLI
First install the edgeware-cli from npm with either of the following commands

npm i -g edgeware-cli

yarn global add edgeware-cli
### Bonding with example
edge -s $SEED staking bond $CONTROLLER_B58_ADDRESS $AMOUNT_IN_EDG stash

edge -s "axis service this custom because top clap sock weekend tenant vehicle merge" staking bond 10 stash // bond 10 EDG (10 * 10^18 currency units)
### Setting session keys with example
edge -s $SEED session setKeys $RESPONSE_FROM_ROTATE_KEYS 0x

edge -s "axis service this custom because top clap sock weekend tenant vehicle merge" session setKeys 0fea2a18acbd19e4a21c3ae29ecefee61d32d46dc4b9a9c5ccecbbbdff7b0a7e8e55bd3035d18f40d8dd1b5d940c47066ddb6f37ec7261d69121e8353d612d1410f7b7f954b3225b148c5de650e0bc3c941ae65e1557c3805c3b0df37285c3892cc2f99d97254ffdf1640c29dff2c6272dbf4dc8dedb46e43ba0bd12ab269b3c 0x // set session keys to the 4 concatentated keys submitted
### Setting validator preferences
edge -s $SEED staking validate $PERCENTAGE

edge -s "axis service this custom because top clap sock weekend tenant vehicle merge" staking validate 10 // set validator preferences to 10% commission
