We're gearing up to have a distributed launch. While it's great for decentralization, it can be a little tough for coordination, especially given the open participation of the lockdrop. With that said, there are a few preliminary rules we want to set to be included as a validator in the initial genesis spec.

At launch, we plan on having 25-50 nodes in the active set; To be in the set, validators should perform a few actions:

- should have validated in the testnet for at least 7 consecutive days. If the testnet changes substantially, we'll require people to validate on the updated version of the testnet (but the goal there is only to ensure that we have working validators at launch). Here's an updated node. 
- should auth into Commonwealth (with your email or Github). We'll be communicating directly through Commonwealth and create a Telegram group for communications.
- should create a thread introducing yourself with positions on Edgeware governance and growth. In addition to bonding the EDG token at your address, it'll also be necessary for delegators to select with whom to delegate. This ensures enhanced security of the network. I'll link to the Commonwealth Labs answers, below. 

Here's the latest Edgeware-node -> https://github.com/hicommonwealth/edgeware-node

To set additional expectations, two important notes should be considered.

- **The first month should be considered betanet.** (In testnet 0.8.0, we'll trial using the council to turn on token transfers.)
- **We're planning on keeping token transfers *off* at launch, by setting the transfer fee to MAX_BLOCKS.** After two weeks to a month of stability, we'll create a signaling proposal to activate transfers. This should be an exciting first test of Edgeware governance.
