Edgeware is a Substrate-based blockchain. If you're not familiar with [Substrate](https://substrate.dev/), it is a modular 'build-your-own' blockchain layer built by Parity Technologies that enables Edgeware's forkless upgrades, WASM runtime, and other benefits.

Substate is also a cutting-edge and fast-paced development by its own right. As time goes on, the version of Substrate that Edgeware is based upon will change, and we will periodically need or want to incorporate these changes into Edgeware.

For the first technology upgrade to Edgeware, we are working to incorporate changes to both the Substrate and Edgeware-specific functions.

**Substrate Improvements**
Since the launch of Edgeware Mainnet in November, many enhancements to Substrate have occured, for example:

- Changes to the balances and system modules.
- Basically the migration here moved "accounts" from the balances module to the system module.
- Resource efficiencies over previous versions.

For more details about this part of the upgrade, see [Edgeware PR 158](https://github.com/hicommonwealth/edgeware-node/pull/158), which pegs to the Substrate [PR #5197.](https://github.com/paritytech/substrate/pull/5197)

**Edgeware Improvements**
Meanwhile, Edgeware also has improvements to be deployed. We discuss these changes in Drew Stone's recent post, [Tech Update #1](https://commonwealth.im/edgeware/proposal/discussion/376-tech-update-1-finality-staking-recommendations-and-our-first-upgrade). These changes include, for example:

- Staking improvements
- Finality improvements.
- Session and era length changes

See the post for more details on the Edgeware-specific upgrade details.

### Process
The general process for these upgrades is:

1. Add any migrations and upgrades into [our substrate fork.](https://github.com/hicommonwealth/substrate)
- Run and test this node locally.
- Run through migration and upgrade on Berlin and observe functionality.
- Propose upgrade on Edgeware.

As of this week, the testnet node software with these changes incorporated has been released, and the discussion on the functionality happens at [this thread, by Drew Stone.](https://commonwealth.im/edgeware/proposal/discussion/432-bergmannkiez-v305testnet-status-thread) Once the Testnet has run unproblematically with these upgrades for 1-2 weeks, both sets of feature changes will be combined into a single upgrade proposal for Edgeware Mainnet.

### Contingency
In the event of any breaking issues (bricked chain, etc.), we will need to revert the chain back to the point before the upgrade. Thus the following process- which requires strong coordination on validators, is needed:

1. Mark a block before the upgrade is planned.
2. Publish thread on Commonwealth, Telegram, etc. to using --revert command on Edgeware to revert to the chosen block.
