## **Summary**

A user interface for displaying staking statistics at a system level and at an individual validator and nominator level. Users should be able to see how much earnings and losses they have over time based on reward and slashing events and be able to embed these into their profiles. Users should also be able to see expected returns from staking activities with pretty graphs.

## **Goals**

- See global statistics of the staking module
    - How much is staked vs overall percentage
    - How much is nominated
    - Total number of nominators/validators
- Lookup staking stats by a substrate validator and nominator address
    - See ImOnline/Offence statistics
    - See if a validator was slashed, when that occurred, and how much the slash is
    - See if a validator was rewarded, when that occurred, and how much the reward is
- See the stash, controller, and authority keys for validator
- See the nominators for a validator and click into each one to go to profile

## **User stories / Test cases**

- As a user, when I search for a validator, I should be presented with details and information about their staking activities either on their profile or separate page.
    - I should see a list of slashes and rewards with their amounts
    - I should see the list of current nominators
    - I should see the current keys associated with the validator
    - I should see the identity of the validator if it exists
- As a user, when I visit the staking/validator home page I should see global statistics of the staking module. I should see how many validators and nominators there are:
    - I should see a list of the current validators on the homepage
    - I should see a search bar where I can type in an EDG address that displays either info about the validator or none at all if the address is not a validator
    - I should be able to click on validator addresses and see stats about the individual validator from the events we store
- I should see the percentage of money is staked in the module
- I should see the ImOnline and Offences events since these are general and grouped

## **Implementation Plan**

- Data should be loaded directly from the Polkadot api and historical data should be stored and loaded from the database
    - You should grab events and filter for Staking, ImOnline, and Offence related events. You should use the ChainEvent logic to ensure these events are collected and if so, grab the event data from the database
    - You should implement getters for making it easy to grab this data and present it in views.
- Events from the chain should be stored in memory or in an auxiliary DB by default (this functionality should exist already with the new ChainEvent logic)
- Create a homepage that displays the global statistics on staking
- Allow search functionality to get statistics about a specific validator by inputting a validator address and use autocomplete to auto-populate these search queries
    - Create an input to submit addresses for searching this data on the homepage
    - Allow clicking validator addresses as buttons or "a" tags to complement the search functionality
