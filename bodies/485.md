# The Latest
Alexander from Parity and I have been compiling migrations and updating the node against substrate master. Since we started more than 1 month ago, we've gathered a number of migrations related to balances, hashers, staking, and accounts — a total of 8 migrations. Additionally, we've updated the node many times against the substrate master branch and are continuously testing the upgrade flows for networks with old and new nodes before and after an upgrade. As this maintenance project is composed of integrating changes across 4 months of active work on Substrate, it is quite substantial and has been a very time-intensive process.

# Functional Changes
### Staking
For the staking migration, future changes will impact the payout schemes for nominators and validators. We will move to a simple payout scheme that is now live on Kusama/Substrate where validators can claim payouts for themselves and their nominators in one flow.

### Iterable Storage Maps
From the opaque hashes migration, Edgeware storage maps will now be iterable which was previously unavailable. This is a nice feature to have for any projects building on Edgeware as it allows them to search through maps directly without directly knowing keys for key/value pairs.

## Remaining work
The remaining migrations are tracked [here](https://github.com/hicommonwealth/edgeware-node/issues/164). For the balances migration we will also need to collect every Edgeware account to migrate the storage locations of balances. This task is ongoing and will begin more extensive work next week.
Once we collect all migrations, we will undergo a period of testing these changes on local networks to ensure that there is a stable path for old and new node operators when these changes take effect on Mainnet.
