## Overview 
With the upcoming runtime upgrade to Edgeware mainnet, there is a need to coordinate a node upgrade with validators and node operators. When and if the runtime upgrade is passed and enacted, all old and outdated Edgeware nodes will not function properly out-of-the-box.

To that end, we will need everyone to upgrade their nodes to version 3.0.8 that is now in release for Edgeware Mainnet on Github. Running the 3.0.8 can be configured with some extra parameters to sync the chain faster and reduce lagging at the end of eras. These configuration settings are in the following doc:

[https://github.com/hicommonwealth/edgeware-node/releases/tag/v3.0.8](https://github.com/hicommonwealth/edgeware-node/releases/tag/v3.0.8)

## Proposal Plan
When 90%+ of nodes on mainnet begin running the new node v3.0.8, then we will push the upgrade through the democracy system.
For nodes that have not upgraded, we will apply the judgement below.

## Slash reimbursement positioning
There has been a decent amount of conversation around the nodes stalling as operators upgrade their setups, and so we want to address our positioning in the event that there are issues before and after upgrade.

So far all upgraded nodes are working quite well, without issues on the existing mainnet network. They are producing blocks, not stalling with the right configuration, and don't seem to be producing any issues. However, after running the upgrade this may not hold. Obviously, we will have to wait and find out.

**The case in which Commonwealth supports reimbursement / cancelling of slashes is if:**

- Node operators upgraded their nodes and experienced issues immediately after upgrade.


**Commonwealth maintains the position that we will not reimburse funds for slashes or vote to cancel them if:**

- Node operators do not upgrade their nodes in a reasonable period of time ~2 weeks.


_**NOTE: We will vote using this positioning, it is no guarantee that any proposal will go through in the event of slashes.**_
