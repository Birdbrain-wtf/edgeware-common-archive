## **Edgeware Community ERUP-5 upgrade update **

Earlier this year a [proposal was approved](https://commonwealth.im/edgeware/discussion/3608-recruitment-of-flipchan-as-edgeware-runtime-core-developer) to address Edgeware's core runtime issues and I (Filip/[@Flipchan](/edgeware/account/mdqwzsGFQ8jq2DQ246a9q3FhUAYKrmvNFEfYALXMWiueijV) flipchan) started on the development.

The goal of this proposal was to upgrade Edgeware's runtime and design structure so that we as a community can follow the polkadot-v releases of Substrate. 

Initially the process of this upgrade seemed pretty straightforward but the difficulty was largely under estimated. 

Edgeware's node is currently not running the official Substrate packages from Parity as they were forked as an early design decision. 

The beginning of ERUP-5 was spent switching to the official version of Substrate. 

Edgeware has an EVM implementation which has not been maintained for a while, causing the code to not be compatible with the latest Substrate releases. 

Edgeware also has its own Ethereum pallet fork (Frontier). I saw after a while that the official version of Frontier was not up to date so I started to rewrite Edgeware's Frontier to use the official Polkadot releases and its currently working and compiling with the polkadot-v0.9.18 branch. 

After this was done, Ethereum had pushed a lot of new updates and several new changes such as new transaction formats. After countless hours of manually upgrading the Ethereum implementation, making sure it syncs with the new Frontier and so on, the problems started to increase. 

After the runtime was upgraded and the Ethereum implementation put in place, which included the Ethereum upgrade that expanded the transaction compatibility. 

During this process lots more libraries started to break and after hours of debugging the node is now building up to the last point where it needs to produce a webassembly build. 

The current road block is that the node is not properly producing a WASM build.

This upgrade has been very painful, taken too long and now when the proccess looks near the finish line, we need to solve the std leak. 

## **What's was the big obstacle? **

Making the node build WASM

The problem is not directly Ethereum related as the problem was that Substrate said that we were not properly building a webassembly version.

This path has been long and now when finally Edgeware’s Frontier version is working and compiling, we need to solve the build errors. 
Other substrate based chains have enabled various versions of Frontier together with their own sticks and glue to keep it together.

Making Substrate work with Ethereum is a great feature list that we have and to be clear Ethereum is not our current bottle-neck.

This seems to be a similar problem as other people have had it stack exchange:

## **A feature list of things in the erup-5-latest branch**

- Switched to official Substrate releases from Parity 
- Several rpc upgrades 
- Support for the latest Ethereum transaction formats 
- Support for the latest Substrate types 
- Upgrade to clap for the cli custom Frontier pallet


## **Summary points**

5 months for an upgrade is not suitable - it was a far bigger challenge than we anticipated.

However with the major corner-stones now achieved we can move on to following the Substrate Polkadot releases with our updated runtime. 

This maintenance work will be far easier when done in small, consistent steps, rather than the major catchup for ERUP5.

There will be a proposal to cover this work going forward.
