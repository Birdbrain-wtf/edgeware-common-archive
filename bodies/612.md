# Upgrade 1
Upgrade 1 moved Edgeware to Substrate 2.0 rc3 within the Edgeware Node v3.0.8.


### Addressing Finality Issues
As it stands, the Edgeware node has been having some issues with validators not voting in the finalization process, leading finalization to stall and eventually triggering forced GRANDPA set updates. Not long ago with the help of [Andre Silva](%5B%3Chttps://github.com/andresilva%3E%5D(%3Chttps://github.com/andresilva%3E)) we merged in some changes to the GRANDPA service worker, and turned off forced finality changes to the Edgeware runtime. These changes will make their way into the first Edgeware runtime upgrade.
For technical details, please refer to:
1. [Disable GRANDPA finality fallback](%5B%3Chttps://github.com/hicommonwealth/edgeware-node/pull/141%3E%5D(%3Chttps://github.com/hicommonwealth/edgeware-node/pull/141%3E))
2. [Disable GRANDPA observer](%5B%3Chttps://github.com/hicommonwealth/edgeware-node/pull/140%3E%5D(%3Chttps://github.com/hicommonwealth/edgeware-node/pull/140%3E))

Additionally, we have repaired
1. Crashes in the v1.0.1 node due to inproper time arithmetic
2. Memory leaks in the Edgeware node


### Migrations
In order to prepare for the upgrade to Substrate 2, several migrations of data within the chain were included. Edgeware launched with the balances and vesting module as separate modules. After the launch of Edgeware, however, another change was made to the storage of user account balances in Substrate, and user accounts and their balances are now managed under the system module and not the balances module (necessitating that we migrate user accounts from the balances to the system module,)

### Staking
For the staking migration, future changes will impact the payout schemes for nominators and validators. _We will move to a simple payout scheme that is now live on Kusama/Substrate where validators can claim payouts for themselves and their nominators in one flow._

### Iterable Storage Maps
From the opaque hashes migration, Edgeware storage maps will now be iterable which was previously unavailable. This is a nice feature to have for any projects building on Edgeware as it allows them to search through maps directly without directly knowing keys for key/value pairs.

### Treasury Reward
The treasury reward module parameters are now also updatable by governance thanks to a contribution from remz
1. [Exposure Parameters](https://github.com/hicommonwealth/edgeware-node/pull/161) 


### Parameter updates
Below are notable values of the runtime that have changed.
- 1 hour sessions
- 6 hour eras
- 2 week bonding duration
- 1 week slash deferral
- 128 max nominators rewarded
- 3/4 of council to cancel slashes
- ExternalMajorityOrigin 60%
- FastTrackOrigin 75%
- CancellationOrigin 66%
- 2 week council motion duration
- Treasury ApproveOrigin 60%
- Treasury RejectOrigin 50%
