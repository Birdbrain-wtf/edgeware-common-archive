Toying with an idea where bridges are themselves privacy mixers. The basic premise is:
1. Sending assets across the bridge can be claimed by any account that presents a signature of knowledge over a discrete log, hash preimage, etc.
2. A depositor can repeatedly withdraw arbitrary sub-values for a given bridge transaction. This preserves sender/receiver anonymity by making it harder to reconstruct matching inputs/outputs.


Not sure I've seen prior work in this direction and interested to continue sharing thoughts, formalisms, etc. I see the main problem as figuring out how to preserve anonymity on the receiving end.

More formally, consider a real number _**r = r1 + r2 + ... + rN**_. For a bridge depositing transaction of value _**r**_, we want to enable a receiver to withdraw from the bridge any values _**r_i**_ while preserving sender/receiver anonymity. Define a sender/receiver anonymity _**(1-p)**_ where _**p **_is the probability that an adversary watching the inputs/outputs of the bridge can link a single sender and receiver successfully as the time _**t -> infinity**_. Thus we want _**p -> 0 **_as _**t -> infinity**_.

Some initial ideas:
- Consider a hash function _**H**_, field _**F**_, AND elliptic curve _**E**_. Sample either a random element from _**F**_ or curve point from _**E**_, call this _**x**_.
- Given the deposit amount _**r**_, compute the following hash _**H^r(x).**_
- Withdraw from the bridge by proving some knowledge of an intermediate hash _**H^(r')(x)**_ to withdraw a value _**r' = r_i + r_j + r_k**_ and prove all necessary claims over the original claim (there's probably a lot more to think through here).


I see a problem around this not being possible, mostly due to not being able to track half-claimed deposits. It would be hard to link hashes together to prove that a person isn't withdrawing more than they should be allowed to. Nonetheless, wanted to spark the discussion.
