### Staking UI Updates & Info
Reference: [https://github.com/orgs/hicommonwealth/projects/4](https://github.com/orgs/hicommonwealth/projects/4)

**1) Validators Page: (Merged in Staking UI)**
- Moved API calls for fetching data from front-end to backend.
- Implemented the following APIs to retrieve the information needed to be shown on the UI:
- The /getValidatorsNamesAndAddresses route fetches the address and names of the validator (active, waiting) from the Valdators table
- /getValidatorDetails takes a list of addresses of validators as input and returns the following details: **totalStake**, **ownStake**, **othersStake**, **commission**, **APR, 30 day rewards count, 30 day slashes count, 30 day offenses count.** The route fetches all this data from the HistoricalValidatorStatistics table
- The /getGlobalStatistics route is responsible for fetching and computing stats to be shown on the header of the validators page. These stats include: **numOfValidators, numOfWaitingValidators, totalEras, totalSession, lastBlock#, totalStakedAmount, stakedPercent, estimatedAPR.** All the data is fetched from the chain except **estimatedAPR**. This is computed on every API call using the APR of validators stored in HistoricalValidatorStatistics
- Implemented search functionality to search validators using their name or address. For every keystroke, the list of validators is matched against the input string and the validators in the list are shown/hidden if the search string matches the name/address of the validator
- Paginated the validator view to retrieve data for 20 validators at a time


**2) Validator Details Page: (Merged in Staking UI)**
- Implemented the following APIs:
- The /getValidatorHeaderStats route returns the following details that are displayed in header of the page: APR, uptime%, rewards (count, value), slashes (count, value) and offenses (count). APR, uptime% and 30 days values are fetched from HistoricalValidatorStatistics while the values for rewards, slashes and offenses since the birth of the validator are fetched from the chain-events table using the /getRewards , /getSlashes and /getOffences routes.
- The /getRewards route fetches rewards earned by the validator over time (block)
- The /getSlashes route gets slashes for validators over time (block)
- The /getOffences route gets offenses
- The /getNominatorsOverTime route returns the number of nominators a validator has over time (block)
- The /getTotalStakeOverTime route returns the total stake of the validator over time (block)
- The /getOwnStakeOverTime route returns the own stake of a validator over time (block)
- The /getOtherStakeOverTime route returns others stake over time
- The /getNominatorsOverTime route returns the number of nominators over time
- ChartJs is used for creating the graphs. Graphs show the block number over the x-axis and values (in million, percentage or count) on the y-axis. For every block number we have a reward, slash, offense, etc. The graphs show data bucket-wise and we have defined a bucket size of 27000 blocks, showing 8 buckets on the graph. For every bucket the average of the value over the bucket is plotted on the graph.

**5) Event Handlers: (Merged in Staking UI)**
- New Session Event Handler: Executes on a new session event. Updates the Validators table with new validators. Updates the HistoricalValidatorStatistics table replicating the last record of each validator and then updating their exposure
- Slashes Event Handler: Executes on a slash event. Creates a new entry in HistoricalValidatorStatistics for the validator being slashed by replicating their last record of the db. It updates the exposure and **slashesStats** (count. sum, avg). If a nominator is being slashed, then the record of its validator is updated. One case not handled at the moment is what if the nominator being slashed is nominating multiple validators - in such a case which validator should have their exposure updated?
- Bond/Unbond Event Handler: Executes on bond and unbond events. It updates the exposure of the validator with the amount bonded or unbonded
- SomeOffline Event Handler: Executes when an offline event occurs. It replicates the last record of the validators in someOffline event and decreases their uptime%.
- All Good Event Handler: Executes when the all good event triggers. In this case the uptime% of the validators is incremented!
- Offence Event Handler: Replicates the last record of the validator from the db and updates their offenceStats.
- Rewards Event Handler: Triggers when a reward event is fired! For each validator who receives the reward, it updates their exposure if the destination is staking. It also recomputes the APR of the validator who received the reward. APR is computed based on the rewards received by the validator in last 30 days.
- Heartbeat Handler: Writes the address of the person who sent the heartbeat to the console
