Hey Edgeware community, here's our progress since the last update:
- Added a new mode to the chain-events listener called archival which allows the listener to poll previous blocks all the way from block 0 up to the current head. It makes use of a rpc call api.rpc.chain.getBlockHash(number) to query past blocks
- The enricher for new session events was revisited and updated to take into account that the events being received are not necessarily at the head of the chain. This incurred a multitude of changes, including:
1. Updating the api call to fetch current era — before the upgrade, api.query.staking.currentEra returned a string, but after the edgeware-node upgrade, the api returns an option — so changes were made to ensure that regardless of which block is being received by the enricher, it should be able to extract the era that the block belongs to
2. Updating the api call to get the validators for the received block. Rather then getting blocks using api.derive.staking.validators() which always returns validators for the session of the header block, retreving validator list using [api.query.session.validators.at](<http://api.query.session.validators.at/>)(hash)
3. Since session.validators only returns the active validator, introduced api.query.staking.erasStakers api call to extract the nextElected validators list
4. To fetch the era rewards points earned by a user, made a separate script that checks the availability of api calls api.query.staking.erasRewardPoints and pi.query.staking.currentEraPointsEarned and returns EraRewardPoints object containing the required data.
5. For fetching details like accountId, controllerId, validatorPrefs, rewardDestination from header block an api.derive.staking.electedInfo call was previously being used. Since this call does not support .at() functionality, we had to fetch all these details from separate api calls including: api.query.staking.erasValidatorPrefs , api.query.staking.validators api.query.staking.payee and api.query.staking.bonded
6. Handled how nextSessionKeys can be fetched for the blocks before and after the upgrade
7. StakersCall was updated to retrieve exposure for blocks before and after the upgrade of node


A PR for chain-events is in draft mode. After final testing, it will be raised so that the folks at Edgeware can review and merge it. The next step is to revisit and update the other enrichers along the same footsteps, so that archival blocks can be correctly processed and stored in the db
- Updated the server.ts script to handle the archival flag, which starts the server in archival mode, fetching data from block(0) or the latest block in the db to the head of the node
- Tested and made changes to NewSessionEventHandler to process the events data being generated by the updated enricher
