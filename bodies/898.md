One of the most common questions we receive time and time again is whether Edgeware will be a parachain. The short answer is yes; the long answer can maybe be described in this proposal. As this is a proposal this is not binding, but merely some ideas and suggestions for a future path to parachain pride.

This chain is to be called Hedgeware, as a hedge against the difficulties of swapping consensus of the current Edgeware for Polkadot consensus. Little is known or spoken about this process from Parity and so new action is potentially called for. Most "parachains" in the ecosystem aren't even live chains and will likely never need to deal with the qualms of swapping consensus.

**The basics of this proposal are as follows:**
- Create and launch Hedgeware as a parachain from day 1.
- Continue to work on and fund swappable consensus work.

**Why?**
- A canary network has been mentioned before, this serves as that.
- Swapping consensus for Edgeware validators could be a messy process and lead to consensus failures on Edgeware.
- Edgeware wants to be a parachain in one form or another.

# Proposal
The proposal put forth is as follows: to build out a parachain called Hedgeware with a different genesis distribution, one that reflects the activity in the community through engineering, discussion, and governance efforts more closely.
The crux of this proposal is in the distribution and in reaching agreement on whether this should be pursued. To that end, we propose:
- 10% to CW Labs
- 5% to developers for ongoing maintenance
- 20% reserved for Kusama parachain bonding
- 1/2 for the initial crowdfund for Kusama Holders
- 1/2 in a DAC to acquire KSM
- 65% to an updated lockdrop distribution

## Updated Distribution
The updated distribution favors accounts that have used the network in some way or another.
**One route:** We first start with the original lockdrop distribution and add the following multipliers to certain addresses. Then we re-normalise the amounts against the proportional allocation of the EDG and generate the HEDG distribution.
**Another route**: We first start with the distribution of EDG on January 1st 2021. We apply the following multipliers and re-normalise the amounts against the proportional allocation of the EDG and generate the HEDG distribution.
### One idea
1. Every address that has transacted at least 10 times receives a 2x bonus.
2. Every address that has voted in a democracy proposal receivies a 3x bonus.
3. Every address that has voted for a council member receives a 4x bonus.
4. Every address that has launched a smart contract receives a 5x bonus.
5. Every validator stash & controller receives a 5x bonus.

### Another idea

2.  (1 + **T(a)** / 100).

4. Let **C(a)** be the number of council election cycles **a** has voted in. The bonus for **a** for voting is (1 + **C(a)** / 10)

6. Let **V(a)** be the number of eras **a** validated in with a stash/controller pair. The bonus for **a** is (1 + **V(a)** / **TOTAL_ERAS)**
