## Project ideas
The current working implementations myself and Filip have worked on are a group/membership pallet for my new project, **Webb**. While we're working on some interesting financial tools, we discussed today more identity and social related projects:
1. Merkle-izing large parts of the Twitter user graph into these trees for proving membership on-chain as well as proving claims about one's follower count, etc.
2. Building a KYC tree with user data for individuals that have passed a KYC of some sort. If we grow this tree over time, then applications that require KYCs can leverage this to build their applications on top.
3. Finding use-cases for using **polynomial commitments** in these merkle trees. This would allow people to prove they know a commitment, multiple times (scaling with the # of roots in the polynomials being committed to).
4. First idea is to utilise this for voting. As long as I'm in the tree and can prove so without **double-using** proofs, I can vote in some abstract system / DAO
5. Second idea is to leverage this for anonymous chat / forum / messaging applications. Basically, every message provides a proof, which exposes a root of a committed polynomial. If users re-append new commitments every day/week/month, it's unlikely they'd run out of these _session keys_ per se (the _session keys_ are the proofs).
6. Games like Dark Forest on Ethereum. The infrastructure is coming along for people to utilise membership tree to add all kinds of data. It is worth exploring what the minimal set of mechanisms would be to support different games. Maybe there is a reduction one can make for games involving **N** players or **M **moves where we can utilise the same circuit and merkle trees just with different preimage data.


Other ideas that have been explored in the Ethereum space: https://github.com/appliedzkp/semaphore
