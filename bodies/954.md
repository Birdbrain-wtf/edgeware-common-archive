Reposting a proposal that Shoeb shared with me for community feedback. I have been working with Shoeb for some time and he helped work on a RenVM pallet for integrating into Edgeware. As we have decided in conjunction with the Ren team to let them deploy their infrastructure to the EVM once live, we feel it's necessary to bridge those assets to the native system as well for future pallets, for example even allowing the Treasury to custody EVM assets.

# Proposal: Build an asset wrapper (bridge) between Edgeware's EVM and Edgeware Native Assets

## Project Overview :page_facing_up:
Edge-x-Ren

https://commonwealth.im/edgeware/proposal/discussion/729-edgeware-x-ren-project-collaboration

Integrating RenVM with Edgeware will bring tokens from any blockchain that RenVM supports into the Edgeware ecosystem

## Development Roadmap :nut_and_bolt:

RenVM will be integrated into Edgeware using the EVM pallet

### Milestone 1

**Mimic the RenVM ethereum solidity contracts on the Edgeware EVM pallet**
* Replication of the solidity contracts in the EVM pallet
* Appropriately configuring the contract parameters
* Testing and benchmarking


### Milestone 2

**Representing the RenVM tokens as assets in the edge-assets pallet**
* Upgrading the edge-assets pallet for dynamic CRUD of assets
* Coupling the assets on the edge-assets pallet with the Ren tokens on the EVM pallet
* Testing and benchmarking

### Work Done

**RenVM integration into Edgeware as a runtime module with on-chain governance handling token/asset management**

For bridging to RenVM:
* Acala's renvm-bridge module was adapted to support multiple tokens, with the token CRUD handled by on-chain governance
* Parts-per-million fee for using the bridge was implemented
* Bitcoin address validation was implemented, but later removed due to a dependency conflict  

For asset management:
* The pallet-assets from substrate master was used. This attempt failed, as the pallets function calls were not public
* The pallet-assets from substrate was upgraded by Drew to support traits. The PR is yet to be merged. Also, this version lacked token CRUD
* Finally, the the pallet-assets from substrate was cloned into edge-assets, and then further upgraded to support asset CRUD through traits

Testing and benchmarking was completed

**Call with the RenVM team**
* RenVM token/asset handling using on-chain governance will require manual intervention, and hence is not a scalable solution
* RenVM integration using a runtime module will require a full audit of the code
* Approach to be taken henceforth is to use the audited ethereum solidity code for RenVM, which also manages the tokens. This approach will be straightforward in the contract replication step, but the RenVM tokens will have to be coupled to the edge-assets pallet to be available to the rest of Edgeware
