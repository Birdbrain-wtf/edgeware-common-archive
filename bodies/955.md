Edgeware should allow a 3rd party to completely subsidize or pay transaction fees on behalf of users (i.e a protocol team or treasury) for a certain period of time. These are not fully fleshed out, but present some ideas to explore. This area seems relatively underexplored. Any radical change like this seems extremely unlikely to be added to Ethereum, and seems better for an opinionated network like Edgeware.

**Why Adopt Something Like this?**

- Zero fees are the best user experience and can increase usage for protocols.
- Differentiated fee model should work for different use cases (I.e as Edgeware supports social, overkill for users to pay for every TX)
- Would create a clear reason to onboard existing teams into the Edgeware / Polkadot Ecosystem (feeless side-chain with access to Polkadot Ecosystem) 


Even though Edgeware has a wide distribution, protocols, and applications built on top and their eventual users. At worst, getting access to the underlying network token is an inconvenience, and at worst is a challenge for users. This model works relatively well when users are used to paying a fee, I.e in DeFi. We are used to paying a transaction cost associated with every transaction. On Ethereum, transaction fees are killer often pricing out smaller users, this is already why some people are thinking of moving onto Edgeware.

Second, for certain applications, the act of signing a transaction itself can often break a user flow. If for a decentralized social network, I had to sign for every interaction using Polkadot Extensions or Metamask, that would be a deal-breaker. 

How can we completely do away with fees for some contracts without breaking the whole chain?

There is some existing precedent for abstracting away these fees:

1. There are some ways to abstract this. [Metatransaction on ETH and xDAI](https://www.xdaichain.com/for-developers/developer-resources/meta-transactions) allows a user to sign a message, where then a 3rd party pays the cost of the transaction.
2. Parachains themselves also abstract the need for accounts to [individual hold DOTs](https://wiki.polkadot.network/docs/en/learn-transaction-fees#shard-transactions) but allow addresses to interact across different parachains for a set period of time.


**What Would Something Like to Protocols?**

Zero Network Fees could be a pretty big killer value proposition for any DeFi protocol that wants to drive additional usage. In TradFi, Robinhood scaled quickly by offering free brokerage services, a model that other firms were forced to adopt. Zero fees when coupled with vampire migrations could quickly flip usage.

Protocols and treasuries are already paying for various services, I.e for Chainlink oracles directly from the treasury. To provide zero-fee transactions, teams could allocate a portion of the supply of their token and raise from the Edgeware Treasury or from any EDG holder to prepay for a certain period of time, or directly acquire EDG and “stake”.

EDG is a stakeholder-governed platform. So it's important for protocols building on EDG to hold EDG to have a voice in governance, being able to provide zero-fee transactions is an additional bonus.

Given that Edgeware already has a combination of full EVM support, this positions Edgeware as a zero-fee side chain for existing Ethereum Applications. 

**Implementation Multiple Implementations**

There are several levels of runtime integration from least to most chain integration, and also could work as a potential implementation path onto Edgeware. None of these are completely fleshed out.

1. **Relayer / Metatransaction from xDAi and GSN.** Crowdfund EDG then used to purchase Gas Token / Chai equivalents on Edgeware, and run relayers. This is a lot of additional infrastructure for the team to run.
2. **Contract staking (not very fleshed out)**: A contract owner would hold EDG, this EDG could (or would) be staked towards all validators on the network on behalf of a contract. This EDG would generate rewards to validators. As a user creates a transaction, the rewards generated would be used as a “third party” source to subsidize the transaction fee. In effect, a contract would be “paying fees out of inflation”. This is someone similar to NEAR [contract staking](https://docs.near.org/docs/concepts/storage).
3. **Protected Contracts**: Introduce an additional chain primitive. This would be the most similar to a parachain slot auction, there could be several slots that governance could set the weight (and therefore fee) to zero for a set of contract interactions to zero for a certain period of time. Protocols would need to keep EDG continually staked. This also has the highest risk for spam, and so these contracts would need to be watched closely so that they don’t bloat the chain.
