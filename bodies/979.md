One of the great things about smart contracts, and why DeFi / NFTs themselves have flourished, is that a single developer / person can very easily use another project's smart contracts. This is similar to an "APIs", but a bit more powerful because value like money and identity can directly be used. This has led to a much quicker pace of innovation than what we've see in traditional finance or other industries. (Common joke is that DeFi is reinventing all of finance in 5 years, which is basically true).

Can we make pulling funds from the treasury as simple as this? So that a developer, community member, or other contributor can "permissionlessly" add value? I think we can.

You can frame this as "liquidity mining" or an ongoing "token distribution", but for a "useful proof of work." One-off token distribution events have been proposed, such as potential Uniswap MerkleDistribution (a simple proof of interaction that can be verified). Let's do this for things that actually add value to the chain

**Today on Edgeware**

The Edgeware proposal process is pretty messy. A lot of this is just the natural exercise of debate and consensus-building, but it can also be a frustrating part of trying to move forward a decentralized ecosystem. Coordinating the high bandwidth video/call time around a global ecosystem is tough, and when this is repeated across all the important decisions that need to be made, it can be_ frustratingly slow_. 

And then as things do get discussed, there is a "traditional" way of doing things i.e hiring a PR firm, or doing partnerships proposals, and then finally getting things approved by the community/council. It feels like we're still trying to move forward with a traditional company / organization mentality.

Instead, to help scale the community people should be able to "permissionlessly" add value, like developers can with remixing smart contracts. As a chain, there a few broad areas in which the community is pushing towards. Things like:

- Growing the community
- Onboarding new developers / that can create new ideas
- Funding new ideas
- Building more core features
- Onboarding existing protocols


While this won't happen overnight, I'm interested in moving the treasury into a position where those things are "autonomously" incentivized. 

**Permissionless Treasury / Incentives**

The only incentive where there is a clear protocol is validating / nominating. People know what potential rewards will be and can "permissionlessly" add more security to the chain. They don't need to be approved by the council or treasury as an Authority (aka a PoA chain).

Right now, we are essentially PoA for all the other areas. This could change:

- **Community / Marketing: **
- Move from **Traditional PR **to tracking specific metrics around community growth in social channels or registered on-chain identities
- **Onboarding new developers**
- Move from a grants program to bounties (with associated values that can be claimed). 
- **Building and maintaining core features / dev tools**
- Right now a proposal can be funded by a grant, but continuing to fund them isn't the greatest, move towards a system where each pallet or core feature can be grant funded, but also takes a % of the fees that it accrues.
- **Onboarding existing protocols**
- Move from "partnership" announcements and sales to people getting paid as a % of fees that their protocol, or protocol that they've onboarded make sense.


This will be a long process, but it seems really important to having a healthy, growing ecosystem. How would we implement this?

**Oracles**

For each of the areas, we'll need to decide on:

- KPIs
- an amount that that KPI is worth to the chain and
- use governance to just approve those "pools" and for what amount of time


These would still be done and set by governance, but only infrequently, quarterly, biannually, or annually. For example:

- Agree on incentives / KPIs: **Incentivizing protocols to onboard to Edgeware**
- An amount that that KPI is worth to the chain: **20% of the treasury budget**
- use governance to just approve those "pools" and for what amount of time: **3 months upon which any unclaimed rewards return to the treasury**


When someone creates a proposal like this, they will deploy a smart contract, that holds funds that anyone can claim from if they post some proof. We can use smaller trial periods to tune the proof or the KPI until it is doing a good job of aiding the desired behavior.

Each proof will be specific to each KPI--community onboarding, BD, or core development. Individuals would post proofs, which would be verified automatically by oracles, these could include theGraph, Chainlink, our own offchain-workers, or some other on-chain data sources. There could be some "timelock" for clear fraud that the Council could review.

Because we have smart contracts that can automatically "clawback" funds, there is no risk of the governmental bloat problem where the incentive is for departments to spend everything that they can before the EoY.

If these incentives worked really well, then they could directly be enshrined into the chain as "streaming rewards" that are self-perpetuating incentives (based on treasury inflation).

[Chain Leads](https://commonwealth.im/edgeware/proposal/discussion/880-decentralizing-edgeware-with-chain-leads) or other on-chain organizations even if paid, should be able to participate in these rewards as well. And perhaps individuals who do a good job within the community of helping with a specific KPI would be onboarded to the chain.

**Specific Example of Proofs**

Protocol Onboarding Incentives: 

A PoS blockchain is directly related to the fees that are earned. So it makes sense that we want protocols that have a proven history of driving fees on other blockchains to use Edgeware for scaling. If a protocol team wants to deploy their protocol on Edgeware then we should want that. The traditional way would be to try to "partner" with the protocol and announce something. That requires some "authority".

A permissionless way to incentivize the deployment of their fee generating protocol onto Edgeware might be to rebate them some portion of fees generated on Edgeware. For example COMP. A proof might be:
1. Post the code hash of the existing contract
2. Post the address at which the code exists on Edgeware (EVM)
3. Post the address on Ethereum at which the code has been deployed.
4. Add a recipient for the reward


// Now 

1. Check that these code hashes are the same
2. Use an oracle to see the fees that the contract generated on Ethereum for the past 6 months, called "past fees"
3. Hold "past fees" * reward_fraction (Chosen by governance 0.01% of past fees in dollar terms?)
4. Allocate reward if there is still any in the existing contract


// Optional
1. Post signature to prove ownership of the Ethereum Contract's address (or could be the DAO / governance contract if there is "owner) 
  (We do this cause anyone could try to launch the same contract and try to claim the reward, but maybe this is desireable? and becomes a bounty?)

2. Vest the EDG until X amount of fees on Edgeware have been generated by that contract.
The above still has flaws, for example, we probably would not want pure frauds (which sadly are still large ETH gas guzzlers). Also, this could be powerfully combined with [permissionless subsidiaries](https://commonwealth.im/edgeware/proposal/discussion/958-frmr-subdaos-permissionless-subsidaries) to basically create bounties for existing contracts. This also could be extended by adding in a "referral" for a person who does BD to onboard this team / project to Edgeware.
